关键产品取舍

① 本地优先：职业原件与 SQLite 存本机、API Key 存系统凭据；② 人机协同：AI 改写先预览确认并进入待审查状态，绝不静默覆盖；③ 不重造排版轮子：通过公开 REST API 对接 Reactive Resume，专注做好事实治理与快照冻结。

交付与验证

作品集 V1 打通材料导入去重、事实审查、按 JD 选材、内容快照、Reactive Resume 排版、最终 PDF（SHA-256）回流归档与投递登记，并通过前端单测、E2E、Rust 合同测试与重启持久化验证。

佐证原件 (SHA-256) → 事实修订 (人工复审) → 岗位选材组合 → 不可变快照 → PDF 归档与冻结投递
补充说明与当前边界

模型连接已通过本机兼容接口与 Windows 凭据机制验收，真实外部模型效果需按用户所配服务实测；批量材料自动解析、模拟访谈与自动选材优化列在后续迭代计划中。

文档解析 API 质量评测体系与 RTH 交接看板

协助师兄为高频迭代的文档解析 API 打造“无人值守、失败可归因、团队可交接”的质量评测产品：39 天从 0 到稳定运行并交付可视化看板。

  • 评测产品化
  • 状态机定义
  • 架构主动收敛
  • RTH 交接看板
12 晚 / 21,121 轮夜间 cron 断点续跑累计 103万+ 请求
4,800 → 65600 份报告异常降噪 -89.2%，1,183 路径 0 缺失
16 视图 / 158 报告独立 RTH 交接层（HTML + Excel 总入口）

产品与架构取舍

① 先定判定语言再写代码：定义 13 态终态状态机、3 空互斥与 5 类失败归因，用原始 Hash + 纯文本 Hash 区分内容差异与结构差异；② 主动做减法：果断放弃冗余的 6 域重平台，收敛为单一 `round_test` 主链路，保障一人可维护、夜间连跑 12 晚。

安全门与可交接交付

默认 `dry-run`（真实发请求须显式审批）、历史目录只增不改、密钥隔离；针对团队“看懂并接手”的需求，构建内置引擎的 `round_test_handover`（RTH）16 视图看板，实现执行与只读出报告双流解耦。

样本队列与断点 → Baseline + 4 并发对比 → 状态机与 5 类归因 → 降噪漏斗 (-89.2%) → RTH 16 视图交接看板
补充说明与当前边界

11/09 七并发异常夜验证了“轮级归因只回答可不可比，根因必须下钻请求级”，据此推动并发锁 4 与 503 退避。同时明确能力边界：自动化 PASS 只代表与 baseline 一致，不等同于人工 Gold 语义正确性。

12 类

静态一致性校验

Agent Relay Governance：让多 Agent 接力有规则可查

多个 AI Coding Agent 跨会话协作长周期项目时，如何避免上下文爆炸、状态冲突和“没验证就宣称完成”？

  • 协议设计
  • 任务契约
  • SSOT 记忆分工
  • OpenViking 集成

核心设计

将交接单元从自由聊天定义为结构化 Task Contract，用 5 类单一权威文件划分状态/断点/日志/决策/经验，并配套纯 Python 标准库 12 类一致性校验器与冲突转 `HOLD` 人工仲裁规则。

开源集成与试点验证

按需接入 OpenViking 补齐跨阶段历史语义检索，但坚持“返回片段须核对本地 SHA-256 原文、本地文件保留状态权威”。真实工程试点证明：检索提升证据召回，但不能替代状态权威与人工审阅。

Task Contract → SSOT 5 类记忆 → 12 类静态校验 → 可选 OpenViking 检索 → 人工关闸放行
补充说明与当前边界

ARG 是轻量文件协议而非 Agent Runtime，不做并行调度运行时，也不自动判定业务验收是否通过。

DATA OPERATIONS & GOVERNANCE

把数据质量和验收规则写进产品设计里。

好的 AI 产品不是靠单次 Prompt 撞运气，
而是靠清晰的数据契约、质量闸门与复盘闭环。

数据流程设计｜明确输入输出契约

在飞书 Skill 与 API 质量体系中先定义字段标准、终态状态机与异常兜底，确保每一步产出都可校验、可定位。

数据运营｜万级样本口径治理

版本治理｜防止新改写污染历史

在 Career Copilot 中用追加修订与不可变快照隔离“编辑态”和“已投递态”，让 AI 建议始终处于人工可控范围内。

评测验收｜把失败变成可迭代信号

在批量评测中内置超时控制、断点续测与错误归因，把模糊的“效果不好”拆解成可定位的接口、解析、提示词或策略问题。
