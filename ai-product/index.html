Career Copilot：让求职材料与投递版本可追溯

经历散落在多份文件中，针对不同岗位反复改写时，如何管理可信内容并追溯最终投递的版本？

  • 产品流程
  • React / Tauri
  • 本地存储
  • AI 助手

我的工作

从多版本简历、岗位信息分散和经历重复整理的问题出发，拆解职业资产、岗位工作区和 AI 助手的场景，设计并实现本地桌面工作台。

交付产出

打通事实审查、岗位事实组合、内容快照、HTML / Markdown 导出、最终 PDF 登记和投递记录；数据保存在本机并支持重启后继续使用。

从问题到交付

  1. 场景与优先级

    将流程定义为“职业事实 → 岗位要求 → 确认组合 → 内容版本 → 最终 PDF → 投递记录”，优先完成手工可用的纵向链路，再扩展 AI 辅助入口。

  2. 关键产品取舍

    已确认事实才可进入简历组合；上游内容修改不会静默覆盖历史快照。最终 PDF 用摘要校验并与投递记录绑定，让“发出了哪份材料”有明确依据。

  3. AI 交互与验证

    助手只发送用户明确选择的上下文，建议先预览、后确认应用；事实改写创建待审查修订。合成演示与个人工作区分开，通过桌面流程和重启测试检查链路。

职业事实→岗位组合→内容版本→投递记录

补充说明与当前边界

Agent Relay Governance：让多 Agent 接力有规则可查

多个 AI Coding Agent 先后参与同一项目时，如何减少状态丢失、重复执行和交付结果难以追溯的问题？

  • 需求拆解
  • 任务契约
  • 状态管理
  • 验证脚本

我的工作

围绕长周期协作中的交接痛点，设计文件驱动、模型无关的治理协议，用结构化任务契约组织目标、角色、输入输出、依赖关系与验收标准。

交付产出

形成任务状态、恢复检查点、决策与历史记录的管理规则，配套 Python 验证脚本、模板和人工复核机制，支持按统一规范接力执行。

从问题到交付

  1. 定义交接单元

    将交接从一段聊天改为任务契约，明确目标、依赖、产出、验收条件、阻塞原因与下一步动作，让接手者知道任务做到哪里。

  2. 划分信息职责

    当前状态、恢复检查点、决策原因与历史日志各自承担单一职责；按需加载上下文，避免同时维护多个相互冲突的状态来源。

  3. 校验与人工介入

    验证脚本覆盖状态机、任务契约、依赖、验证证据、冻结决策和文件哈希等 12 类一致性；冲突按证据与人工仲裁规则处理，保留接力轨迹。

任务契约→状态与检查点→规则校验→交接恢复
